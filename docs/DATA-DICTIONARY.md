# 计量定义

claim_id唯一；item为清单编码，支持钢筋与001等别名。period为YYYY-MM。累计数量按t或m³保存，当前周期工程量=本次累计-前期已审累计。previous_revisions参数可指定更正后的前审数量，重新计算形成不同批次，不覆盖旧证据。

C0原始价100元，C1自2026-11生效为120元，DRAFT未批准不可结算。负进度必须reversal=approved作为已批冲回标记。扣留质保金5%、预付款扣回10%分别按分量化，净额=本期总额-质保金-预付款扣回，负进度同步冲回扣留。reported为原申报净额，差异=复算净额-reported。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

## 价格调整

`parameters.price_adjustments` 为调价依据列表：`basis_id`唯一标识，`change_id`引用已批变更，`item`为清单编码，`original_price`/`new_price`为元，`retroactive_from`/`retroactive_to`为YYYY-MM半开区间，`status`取已批准/待审批/已撤回/未生效，`effective_period`为可结算起始期。`parameters.settlement_period`默认2026-11。只对结算期之前、追溯区间内、`increment_qty`非零的已签工程量按已签单价与新单价的差额计价，`adjustment_amount=已签量×(新单价-已签单价)`。依据按提交顺序判定：同`basis_id`或同内容视为重复提交；同清单追溯区间重叠且新价与在先原价不衔接视为冲突；重复与冲突均在首次提交处保留、后续隔离。未批准、未生效、已撤回的依据隔离且不参与计价，缺失数据的依据列入`ADJUSTMENT_NO_AFFECTED_QTY`。每条明细带`settlement_key`（依据指纹+申报编号+清单+周期）；签认后写入快照，重跑同一依据时该键对应的明细转为"已结清"，从本期可入账净额中剔除，避免重复计价。复核版本冲突返回409且不登记结清。
